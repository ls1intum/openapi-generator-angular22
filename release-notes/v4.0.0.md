# 4.0.0

This release corrects generated response types and URL-encoded form requests. Regenerating a client can require changes to its callers.

## Breaking changes

### Nullable JSON responses

A JSON service method returns `Observable<T | null>` when a documented success permits a null or absent body, such as `200 Job` plus `204`. A GET resource for the same operation returns `HttpResourceRef<T | null | undefined>`; `undefined` also covers the loading state. Pure bodyless operations still return `Observable<void>`.

A selected JSON success without a schema now returns `unknown` instead of `void`. When the selected success is bodyless, the generator recovers the body type from a later success when available. For responses with multiple media types, the generator selects the JSON schema for a JSON call. These changes can require updates to explicit return types and property access.

Full-response methods still return `HttpResponse<T>`: Angular already types its `body` as `T | null`.

### URL-encoded forms

Requests declared as `application/x-www-form-urlencoded` now send an encoded string with that content type, rather than multipart `FormData`. Update any server or interceptor that worked around the old behavior.

## Added

- Service methods accept an optional `RequestOptions` argument with an `HttpContext` and extra headers. Declared header parameters override caller headers case-insensitively. Resource functions do not take this argument.
- Generated fixtures are type-checked with and without `exactOptionalPropertyTypes`.

## Fixed

- URL-encoded fields use their declared `encoding` style and `explode` settings. Date-only fields mapped to `Date` use `YYYY-MM-DD`.
- Explicit JSON `null` no longer produces an import for a nonexistent `Null` model.
- Nullable properties, array items and map values are preserved in copied nullable object models.

## Migration

1. Update the generator dependency to `de.tum.cit.aet:openapi-generator-angular22:4.0.0` and regenerate the complete client.
2. Handle `null` in affected service results and both `null` and `undefined` in resource values. Validate `unknown` bodies before using them.
3. Update explicit return types affected by recovered or differently selected response bodies.
4. Check URL-encoded endpoints and any interceptors that inspect their bodies.
5. Run the application's TypeScript, template and integration checks.

## Known limitations

- Different successful DTO schemas are not combined into a union.
- Text and Blob methods do not gain nullable types for bodyless successes.
- Resource functions do not accept request options.
- URL-encoded `encoding.contentType` is ignored.
- Multi-model `anyOf` schemas still generate a merged interface.

See the [README](https://github.com/ls1intum/openapi-generator-angular22/blob/main/README.md) for configuration and the other documented limitations.
