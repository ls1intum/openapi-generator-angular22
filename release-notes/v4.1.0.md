# 4.1.0

This release moves the code that appends multipart fields into one shared file. Service method signatures and the parts sent on the wire do not change.

## Changed

- A new supporting file, `api/multipart.ts`, exports one function per kind of multipart field: `appendFile`, `appendText`, `appendDate`, `appendDateTime`, `appendValue`, `appendJson` and `appendJsonArray`, and `appendFiles`, `appendTexts`, `appendDates`, `appendDateTimes` and `appendValues` for each item of an array or set. A service method appends each field with one call, such as `appendFile(formData, 'file', file);`, instead of an inline `if (...) { formData.append(...) }` block. Each function's parameter type states what the field may hold, so the TypeScript compiler rejects a value of the wrong kind.
- A method now takes one line per field instead of three. In the Artemis client, this removed the duplicated blocks Sonar reported between the create and update methods of the attachment video unit service. Two operations with ten or more of the same fields in the same order can still repeat a block long enough for a duplicate-code check.

## Migration

1. Update the generator dependency to `de.tum.cit.aet:openapi-generator-angular22:4.1.0` and regenerate the complete client.
2. Commit the new `api/multipart.ts`.
3. A parameter named like one of these functions is now renamed with a `Param` suffix, as parameters named like other identifiers in the generated code already are.
